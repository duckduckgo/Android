# Personal Information Removal

Personal Information Removal (PIR) scans data broker sites for the user's name, birth year and addresses. A
subscriber with the PIR entitlement opens it from Settings. Their scans also send removal requests (opt-outs) to the
brokers that list them. A user without a subscription gets one free scan: the same profile steps and scan, but
scan-only. Its results ask the user to subscribe for removals. Both flows run in a dashboard web page
(`https://duckduckgo.com/dbp`) inside `PirDashboardWebViewActivity`. The scans run in the `:pir` process, in
WebViews the user never sees, and a "Scan complete" notification opens the dashboard when the first scan ends.

## Sub-features

- `pir-settings-hidden` without a subscription, and with no Play offer for the device's account, Settings shows no PIR row, even with Force Freemium PIR eligibility on.
- `pir-settings-free` with a Play offer and no subscription, Settings shows "Personal Information Removal" with "Find your personal info on sites that sell it." and a "Start Free Scan" button. After the profile is saved, the button reads "View Scan Results".
- `pir-settings-subscriber` with the PIR entitlement, Settings > DuckDuckGo Subscription shows "Personal Information Removal" with the label "Off" until a profile is saved, "On" after. The row opens the dashboard. There is no free scan button.
- `pir-dev-settings` Settings > "PIR dev settings" (internal builds) opens `PirDevSettingsActivity` ("Pir Dev Settings"): Open PIR Dashboard, PIR Scan, PIR Opt-out, PIR Email, View PIR Run events, Broker Config, Reset Freemium PIR State, the two "Simulate free scan" actions, "Show freemium scan complete notification", the "Force Freemium PIR eligibility" switch and the custom dashboard URL.
- `pir-dev-reset` "Reset Freemium PIR State" deletes the profile and every scan result. Reopened, dev settings shows PIR Scan disabled: a tap leaves you on `PirDevSettingsActivity`.
- `pir-free-landing` with no saved profile and no subscription, the dashboard opens on `/dbp/freemium?action=onboarding`: "Find out which sites are selling your info!" and "Try for Free".
- `pir-onboarding` the profile steps, whose paths end in `/names`, `/year` and `/addresses`, then the review page `/dbp/profile` with the "Scan" button. Free and paid onboarding look the same.
- `pir-free-scan` "Scan" saves the profile and starts a scan-only foreground run: `m_dbp_foreground-run_started`, `m_dbp_scan_started` (41 of them in the 54-broker run on 2026-11-25), `m_dbp_foreground-run_completed`, logcat "Scan-only run. Skipping the opt-out phase.", and no opt-out. The dashboard reads "Scanning N of M", then "Scan complete".
- `pir-free-results` after the free scan the dashboard opens on `/dbp/freemium/dashboard`: "Good news, we didn't find any records" (or the records found) with "Learn more" and "Settings". PIR Scan in dev settings is enabled.
- `pir-scan-complete-notification` when the first scan ends, the "Free Personal Information Scan" notification ("Scan complete!" for a subscriber) is posted, and tapping it opens the dashboard.
- `pir-subscriber-dashboard` a subscriber with no saved profile gets the welcome page `/dbp/profile/welcome?action=onboarding` ("Personal Information Removal", "Get Started") and the same profile steps. PIR Scan in dev settings is enabled.
- `pir-subscriber-scan` a subscriber's Scan starts a foreground run over more brokers than the free scan (66 against 54 on 2026-11-25): "Initial scan in progress", then "Scanning N of M". After the scans the run checks for brokers with a match to opt out of. With none it logs "No active parent brokers available for optout. Completing run." and creates no opt-out job. With a match it sends removal requests (Gotchas).
- `pir-subscriber-results` after the scan the dashboard is `/dbp/dashboard`: "Recent scans" with each broker ticked, "Monitoring N sites" and "Next scan is <day>". The "Scan complete!" notification opens it, and the Settings row reads "On".

## How to get to it (user POV)

- Settings > DuckDuckGo Subscription > "Personal Information Removal", for a subscriber with the PIR entitlement (`PirSettingView`). When the device can't run PIR, the row opens `PirDesktopActivity` ("Activate the DuckDuckGo subscription on desktop ...") instead.
- Settings > DuckDuckGo Subscription > "Start Free Scan" or "View Scan Results", for a user without a subscription (`PirFreemiumSettingView`). It shows only when Play offers a plan to the device's account.
- The subscription web flow's page after a purchase (`SubscriptionsWebViewActivity`): its PIR button opens the dashboard, or `PirDesktopActivity` when the device can't run PIR.
- The last step of subscription onboarding after a purchase (`SubscriptionOnboardingPirStepActivity`).
- The "Scan complete" notification after the first scan.
- A remote message (New Tab Page banner or modal) with the `pir.main` deeplink, for the free scan and scan results banners. No external `ddg://` link reaches it.
- Settings > Internal Features > "PIR dev settings" > "Open PIR Dashboard" (internal builds). It opens the dashboard whatever the subscription state, which is the only way to reach the free scan on a device whose account Play offers no plan.

## Driving it with verify.sh

Preconditions: baseline, with Web Content Debugging on. Before any scan, know the subscription state: Settings has a "Personal Information Removal" row under DuckDuckGo Subscription only for a subscriber, and a subscriber's scan sends real opt-out requests (Gotchas). `$V checked trailingSwitch` on PIR dev settings reads Force Freemium PIR eligibility. Turn it off again when done. The proofs don't clear app data, but they change PIR's: Reset Freemium PIR State deletes the saved profile and every result.

- **Settings rows.** Settings, then `$V scroll up` one swipe at a time while collecting `$V text`: a subscriber's row is `primaryText Personal Information Removal` with a `label`. The free row is `pirFreemiumPromo` with `pirFreemiumCta` ("Start Free Scan" or "View Scan Results"). Without a Play offer, neither shows, and the only PIR text is "PIR dev settings".
- **Dev settings.** Settings, `$V scroll up` until `text:PIR dev settings` is visible, tap it: `PirDevSettingsActivity`. The buttons are `pirOpenDashboard`, `pirDebugScan`, `pirDebugOptOut`, `pirDebugEmail`, `viewRunEvents`, `brokerConfig`, `pirResetFreemiumState`, `pirSimulateFreeScanMatches`, `pirSimulateFreeScanNoMatches` and `pirShowFreemiumScanCompleteNotification`. The only `trailingSwitch` is Force Freemium PIR eligibility. `android layout` has no enabled flag, so tap `id:pirDebugScan`: enabled opens `PirDevScanActivity`, disabled stays on dev settings. The screen reads PIR's eligibility when it opens, so leave and reopen it after a reset.
- **Free landing.** Dev settings, Force Freemium PIR eligibility on, `$V tap id:pirOpenDashboard`, `$V assert where PirDashboardWebViewActivity`, `$V wait "text:Try for Free" 20`. `$V web eval 'location.pathname + location.search' duckduckgo.com/dbp` reads `/dbp/freemium?action=onboarding`.
- **Onboarding.** The dashboard's text is in `android layout`, so tap with `text:` selectors. `$V web tap` can hit the hidden second WebView (Gotchas). Poll `location.pathname` and act per step. On `/dbp/freemium`, `$V tap "text:Try for Free"`. On the welcome page, `$V tap "text:Get Started"`. On `/names`, `$V type id:first <first>`, then `$V key back` to close the keyboard, then `$V type id:last <last>`, `$V key back`, `$V tap text:Continue`. On `/year`, `$V tap id:year`, `$V scroll up` until the year shows, tap it, then Continue. On `/addresses`, the city and state fields have generated ids: read them from `$V ui` (`city-...` and `state-...`). Type the city, `$V key back`, tap the state field, scroll to the state and tap it, then Continue. The review page `/dbp/profile` lists the birth year and address with "Edit" buttons. `$V scroll up` until `text:Scan` is visible.
- **Free scan.** Start streaming logcat before the tap (Gotchas). `$V tap text:Scan`. `m_dbp_foreground-run_started` logs within seconds as `PIR-LOGGING: m_dbp_foreground-run_started params: {...}` from `:pir`. The dashboard reads "Scanning 1 of 54", then "Scan complete" with each broker ticked. `m_dbp_foreground-run_completed` ends the run. A free run logs "Scan-only run. Skipping the opt-out phase." and no `m_dbp_optout_stage_start`. Second view: dev settings, reopened, has PIR Scan enabled.
- **Free results.** Reopen the dashboard: `location.pathname` is `/dbp/freemium/dashboard`, and `document.body.innerText` starts "Good news, we didn't find any records" for a name with no matches.
- **Notification.** After the first scan, `adb shell dumpsys notification --noredact` has a record from the app with `android.title=String (Free Personal Information Scan)`. Run `adb shell cmd statusbar expand-notifications`. The shade is a system window, so `$V windows` and `$V` selectors don't list it. `android layout --device <serial> --flat` does: find the node whose `text` is the title, `adb shell input tap` its `center`, and `$V where` prints `PirDashboardWebViewActivity`. Dev settings' "Show freemium scan complete notification" posts the same notification without a scan.
- **Subscriber.** Settings, `$V scroll up` until `text:Personal Information Removal` is visible. The next `$V text` line is its `label` ("Off" with no profile). Tap it, `$V assert where PirDashboardWebViewActivity`, `$V wait "text:Get Started" 20`. Then `location.pathname + location.search` reads `/dbp/profile/welcome?action=onboarding`.
- **Subscriber scan.** Only with the opt-out tripwire running (Gotchas). Walk the profile steps as for the free scan ("Get Started" instead of "Try for Free"), then `$V tap text:Scan`. Stream `PIR-JOB-RUNNER: ` lines along with the pixels: "Executing scan for N eligible scan jobs.", then, with no match, "No active parent brokers available for optout. Completing run.". The run never logs "Scan-only run". It took 6 to 7 minutes. Reopen the dashboard from the Settings row: `location.pathname` is `/dbp/dashboard`. The notification's title is "Scan complete!", tapped as for the free scan. Second view: the Settings row's `label` reads "On". Last, delete the profile with Reset Freemium PIR State (it clears any profile, not only a free one): the row reads "Off" again.

## Gotchas

- A subscriber's scan sends real opt-out requests. With a made-up but plausible name, a broker can list a real person under it, and the run fills that broker's removal form, generates an email and submits it. Free and paid onboarding look the same. Check the subscription state before tapping Scan. A proof that scans while subscribed streams logcat and runs `adb shell am force-stop com.duckduckgo.mobile.android.debug` at the first `New opt-out job records created`, `Executing opt-outs for [1-9]`, `PIR-OPT-OUT: Start thread` or `m_dbp_optout_stage` line. `am force-stop` also stops pending email confirmation until the app is next opened. Use a name that matches nobody: "Qorvexa Zintrabul", 1998, Wheeling, West Virginia matched no broker on 2026-11-24.
- Leave no synthetic profile on a subscribed app. A subscriber's scheduled runs rescan a saved profile and opt out of any new match. Reset Freemium PIR State deletes the profile whatever the subscription state. Run it after a subscriber scan, and before adding a subscription to an app that holds a free scan's profile.
- Settings shows its whole subscription section only when `subscriptions.isEligible()`, which needs a Play offer for the device's account (`SettingsViewModel`). A device signed in to an account that already bought a plan, or one in a region without plans, never shows "Start Free Scan", with or without Force Freemium PIR eligibility. Reach the free scan through PIR dev settings > Open PIR Dashboard.
- Two WebViews are attached while the dashboard is open: the dashboard and a hidden one. `$V web eval` needs the `duckduckgo.com/dbp` URL filter, and `$V web tap` can aim at the hidden one, so tap the dashboard's controls with `text:` and `id:` selectors.
- PIR logs so much that the Pixel 10's logcat buffer holds about a minute. Read the run's pixels by streaming `adb logcat -T <mark> -e '<pattern>'` for the whole run, not with `expect_pixel` afterwards. `adbd` logs the command line of that logcat call, pattern included, so skip lines from `adbd` or the opt-out tripwire fires on its own command.
- The job runner's lines (`PIR-JOB-RUNNER: `) also leave the logcat buffer before the run ends. Stream them with the pixels.
- Run pixels fire in `:pir`, which logs them as `PIR-LOGGING: <name> params: {...}`. The wide events `wide_pir-initial-scan` and `wide_pir-time-to-first-scan-complete` are sent from the main process as `Pixel sent: <name> with params: {...} {...}`, with their fields in the second map, after the app comes back to the front.
- The keyboard covers the next field on the profile steps. Close it with `$V key back` after each `$V type`.
- The birth year and state pickers are native lists. Scroll them with `$V scroll up` until the option is on screen.
- The scan-complete notification is posted once per first scan. Later runs don't post it.
- PIR Scan (`PirDevScanActivity`) runs scans in the main process and creates no opt-out jobs. Profile fields filled in on that screen replace the saved profile.
- No `ddg://` scheme opens a screen from outside, so the `pir.main` remote message link can't be opened with `$V open`.
- The dashboard can report "Scan complete" while the last brokers still show "...", and right after it opens from the notification it shows a loading skeleton. Wait for its text before a screenshot.
- Driven with the android CLI on 2026-11-25 on the Pixel 10 (Android 17, API 37, the user's phone, with the build of `1148506a80`). Without a subscription, a proof passed 17 checks: `pir-settings-hidden`, `pir-dev-settings`, `pir-dev-reset`, `pir-free-landing`, `pir-onboarding`, `pir-free-scan` (54 brokers in about 5 minutes), `pir-free-results` (no records) and `pir-scan-complete-notification`. With a subscription, a proof passed 15 checks with the opt-out tripwire running: `pir-settings-subscriber`, `pir-subscriber-dashboard`, `pir-subscriber-scan` (66 brokers on the dashboard, "Executing scan for 52 eligible scan jobs.", no match, so no opt-out job) and `pir-subscriber-results`, then deleted the profile. Not driven: `pir-settings-free` (Play offers no plan to that phone's account), results with records found, the desktop screen, the subscription onboarding step, the `pir.main` remote message, the PIR button after a purchase, and the PIR Opt-out, PIR Email, Broker Config and run events screens.
